# طرح آماده‌سازی واردکننده فیلم و سریال HexDL برای Masiha

تاریخ بررسی: 2026-10-26 — **فقط تحلیل و آماده‌سازی؛ هیچ فیلمی دانلود یا آپلود نشده است.**

## ۱. نتیجه بررسی منبع
- نشانی: https://hexdl.com/
- معرفی عمومی وب‌سایت، دانلود و تماشای آنلاین فیلم و سریال با دوبله فارسی و زیرنویس را تبلیغ می‌کند؛ **این ادعا به معنی تأیید تک‌تک فیلدها یا لینک‌های هر صفحه نیست.**
- درخواست مستقیم به صفحه اصلی، `/wp-json/` و `/sitemap_index.xml` از سرور Masiha به جای محتوای اثر، HTML صفحه «Bot Verification» برگرداند (HTTP 200 با بدنه CAPTCHA).
- `robots.txt` قابل خواندن است؛ بخش‌هایی مانند `/page/*`، `/search/*` و کوئری‌های جستجو را منع کرده و برای `/mag/*` Allow دارد. دریافت داده انبوه از مسیرهای مسدود یا عبور خودکار از CAPTCHA طراحی نشود.
- **تا دریافت نمونه صفحه واقعی یا API / خروجی مجاز از صاحب سایت، محل دقیق HTML عنوان، کاور، لینک‌های کیفیت، فصل/قسمت و دوبله/زیرنویس قابل تأیید نیست.** از selector حدسی و فرض لینک دانلود واقعی پرهیز شود.
- استفاده از فایل‌های ویدیو/کاور و بازنشر تجاری منوط به داشتن مجوز مناسب است؛ اعلام عمومی لینک دانلود به‌تنهایی مجوز بازنشر نیست.

## ۲. مدل اطلاعات پیشنهادی
`film_titles` (شناسه داخلی، منبع و شناسه خارجی، آدرس پست، movie/series، نام فارسی/اصلی، سال، ژانرهای ساخت‌یافته، کارگردان، بازیگران، خلاصه بازنویسی‌شده، امتیاز عددی، منبع امتیاز، شناسه file_id کاور، وضعیت نشر، تأیید مجوز، تاریخ‌ها)

`film_episodes` (عنوان مادر، شماره فصل و قسمت، عنوان/تاریخ پخش اختیاری، UNIQUE(title_id,season,episode))؛ برای سینمایی parent بدون اپیزود.

`film_variants` (title_id، episode_id اختیاری، کیفیت 480/720/1080/...، کدک/نسخه، زبان، دوبله bool، subtitle enum none/hardsub/softsub/external/unknown، حجم ویدیو، HTTPS source مجاز، روش Telegram sendVideo/sendDocument، `file_id`، `file_unique_id`، وضعیت فایل، زمان آپلود، UNIQUE منطقیِ فیلم+اپیزود+کیفیت+زبان+دوبله+زیرنویس+نسخه). **کیفیت هر فایل مستقل است؛ گمان نکنیم همه کیفیت‌های نوشته‌شده در یک پست لینک سالم دارند.**

`film_import_jobs` و `film_import_events` برای صف و لاگ: discovered -> metadata -> awaiting_rights -> queued -> downloading -> downloaded -> uploading -> uploaded -> verified -> published؛ و failed/retry/deferred. دسته و فایل یکتا؛ جلوگیری از درج مجدد؛ عملیات ادامه‌پذیر بعد از restart.

## ۳. فیلدهای اجباری در بررسی هر اثر
| فیلد | قاعده |
|---|---|
| نوع | movie یا series؛ دستی قابل اصلاح |
| کاور | URL معتبر تصاویر و در نشر `photo.file_id` |
| ژانر، سال، کارگردان، بازیگران، خلاصه | فقط از اطلاعات قابل‌مشاهده یا منبع قانونی مجاز، در نبود داده null نه حدس |
| امتیاز | عدد 0..10 و نام منبع امتیاز (IMDb، TMDb، سایت)؛ بدون منبع null |
| سریال | عنوان مادر، شماره فصل، شماره قسمت برای هر فایل |
| کیفیت | به‌ازای هر لینک/نسخه؛ 480p، 720p، 1080p، 2160p، 10bit/x265 اگر واقعاً وجود داشته باشد |
| دوبله | برای **هر نسخه فایل** yes/no/unknown، نه فقط برچسب کلی پست |
| زیرنویس | برای هر نسخه none/hardsub/softsub/external/unknown |
| لینک‌ها | اعتبار URL و URL final پس از redirect و Content-Type/Length، بدون گذر از CAPTCHA |
| مجوز | ثبت منبع اجازه دانلود و **اجازه انتشار مجدد در ربات** قبل از queue |

## ۴. جریان ورود امن (برای فایل‌های دارای مجوز)
1. کشف لینک صفحات مجاز / API مجاز و استخراج metadata بدون دانلود ویدیو.
2. تطبیق و حذف موارد تکراری با شناسه ثابت منبع + نام/سال/فصل/قسمت، پیش‌نمایش و تأیید مدیر.
3. ثبت نسخه‌های جدا (کیفیت، دوبله، زیرنویس)؛ `ffprobe` برای صحت فایل بعد از دانلود و تأیید حجم واقعی.
4. دانلود **فقط یک فایل هم‌زمان** در پوشه staging محدود به فضا، ذخیره به `.part` و rename اتمیک پس از تکمیل؛ بررسی دیسک قبل از شروع و هنگام دانلود. سرور در زمان بررسی حدود ۱۱ GiB فضای خالی داشت.
5. برای فیلم‌ها از **Telegram Local Bot API Server** با کلیدهای رسمی و endpoint فقط روی loopback استفاده شود؛ Cloud Bot API برای multipart ویدیو معمولاً ۵۰ MB و Local Bot API تا ۲۰۰۰ MB است. برای فایل بزرگ‌تر از سقف، خطای قابل پیگیری / روش مجاز جایگزین، نه ثبت موفقیت جعلی.
6. آپلود توسط همان بات به چت آرشیو اختصاصی و کنترل صحت نتیجه Telegram؛ ذخیره `file_id`، `file_unique_id` و send-method و وضعیت پایدار در تراکنش SQL.
7. فقط **پس از تأیید پاسخ تلگرام و commit دیتابیس** فایل موقت محلی را حذف کن. اگر دانلود/آپلود/DB fail شود فایل زودتر حذف نشود و job ادامه‌پذیر بماند.
8. کاور نیز جداگانه در Telegram ذخیره و photo file_id ثبت شود. فایل خام کاور بعد از commit پاک شود. پیام نخست کاور و مشخصات، پیام دوم دکمه‌های کیفیت/نسخه؛ فایل پس از انتخاب کیفیت از طریق file_id فرستاده شود.
9. دسترسی فقط به فایل‌های دارای مجوز انتشار؛ بدون بازنشر خودکار و انبوه قبل از تأیید.

## ۵. وضعیت کنونی Masiha
- جدول `media_items`، نوع movie/series، فصل، قسمت، کاور، بازیگران، سال، ژانر، زبان، دوبله، زیرنویس، کارگردان، خلاصه و file_id را دارد.
- **گروه‌بندی عنوان/اپیزود/چند کیفیت و منبع امتیاز ندارد**؛ مدل جدید مستقل و سازگار با جدول فعلی اضافه شود تا ۱۷٬۹۸۰ موزیک موجود لطمه نبیند.
- در زمان بررسی هیچ رکورد `kind=film` وجود نداشت.
- روی سرور Local Bot API فعال مشاهده نشد. مسیر آپلود موسیقی محدود به ۴۷ MiB است و **نباید** برای ویدیو دوباره استفاده شود.
- فایل‌های Telegram با file_id به همان بات وابسته‌اند؛ برای بازیابی متقاطع بات از file_unique_id نمی‌توان استفاده کرد.
- مرحله تست: ۱ فیلم مجاز دو کیفیت، ۱ سریال مجاز دو قسمت/دو کیفیت، فایل دارای دوبله یا زیرنویس، خطای دانلود، قطع آپلود، retry، نبود کاور، و خروجی فایل پس از حذف موقت.

## ۶. پیش‌نیازهای مانع راه‌اندازی
1. دریافت دو نمونه قابل‌خواندن **با اجازه دسترسی** (فیلم و سریال، HTML یا API/فید رسمی) برای تعیین دقیق XPath/CSS/API و مدل لینک‌ها.
2. تأیید مجوز دریافت و بازنشر فایل‌ها و تصاویر و رعایت محدودیت‌های منبع.
3. نصب و تست مستقل Local Telegram Bot API، خصوصاً فایل‌های 720/1080 و سقف حجم.
4. مهاجرت افزایشی DB و رابط مدیریت صف و انتخاب کیفیت همراه با تست، سپس راه‌اندازی تدریجی.

این سند عمداً نه CAPTCHA را دور می‌زند، نه لینک حدسی می‌سازد و نه فایل جدیدی دانلود یا منتشر می‌کند.
