# نصب و آپدیت یک‌دستوری Masiha VPN Manager

هدف: **نصب کد و آپدیت کد** کاملاً مستقل از **بازیابی داده‌های مشتریان** باشد.

## ۱. نصب روی سرور جدید Ubuntu 24.04 amd64

فقط یک فرمان روی سرور تازه (با دسترسی sudo):

```bash
curl -fsSL https://raw.githubusercontent.com/masiweb/Masih-panel/upgrade/3x-ui-v3.11.0-migration/install.sh | sudo bash
```

از طریق ترمینال نام دامنه مقصد و ایمیل Let's Encrypt درخواست می‌شود.
همان فرمان Git لازم را نصب می‌کند (اگر نباشد)، آخرین شاخه مهاجرت را
در `/root/Masih-panel` دریافت می‌کند و نصب‌کننده کامل مسیحا را اجرا می‌کند.
DNS دامنه باید به سرور مقصد برسد و TCP/80 و TCP/443 قابل دسترسی باشند.
**نصب روی سروری که 3x-ui یا دیتابیس قبلی دارد ممنوع است**؛ از آپدیت استفاده کنید.

برای اتوماسیون غیرتعاملی، قبل از اجرای همان فرمان مقادیر `DOMAIN` و `EMAIL`
را از محیط root تعیین کنید؛ دستور نصب‌کننده همان مقادیر را می‌خواند.

## ۲. آپدیت روی سرور نصب‌شده

تنها یک فرمان، بدون نیاز به انتقال بکاپ:

```bash
curl -fsSL https://raw.githubusercontent.com/masiweb/Masih-panel/upgrade/3x-ui-v3.11.0-migration/update.sh | sudo bash
```

این فرمان در هر بار اجرا آخرین نسخه شاخه را با `git fetch` و
`merge --ff-only` دریافت می‌کند؛ هرگز مخزن یا فایل‌های تغییرکرده محلی را
به زور بازنویسی نمی‌کند.

اسکریپت آپدیت با دریافت سورس پین‌شده و ابزار Go/Node قابل بررسی، باینری
جدید 3x-ui را در یک مسیر **جداگانه و وابسته به هش patch** می‌سازد.
صفحات اختصاصی مسیحا (موسیقی، فیلم، کاربران، AI و IPsec) به همان روش
نصب اصلی وارد سورس مستقل می‌شوند. رابط standalone در مسیر موقت ساخته
می‌شود؛ بعد از موفقیت ساخت، نسخه فعلی فایل اجرایی، کد و وب‌اپ ذخیره،
نسخه جدید اعمال و سرویس‌های فعال تست می‌شوند.

- **آپدیت به هیچ بکاپی نیاز ندارد.** دیتابیس‌های کاربران یا فروش، حتی اگر
  هنوز از سرور قبلی وارد نشده باشند، مانع آپدیت نرم‌افزار نمی‌شوند.
- هیچ عملیات `restore`، ساخت دیتابیس خالی، تنظیم دامنه، تعویض SSL،
  جایگزینی رمز مدیریت یا انتقال کاربران با دستور آپدیت انجام نمی‌شود.
- ربات/پردازشگر غیرفعال فعال نمی‌شود؛ سرویس‌های فعال پس از اعمال کد
  راه‌اندازی مجدد می‌شوند. ممکن است هنگام تعویض باینری قطع کوتاه رخ دهد.
- اگر ساخت کد پیش از تعویض شکست بخورد، سرویس زنده دست‌نخورده باقی می‌ماند.
  برای مراحل بعدی نسخه بازگشت در `/root/masiha-updates/rollback-.../`
  نگهداری می‌شود.
- فرمان آپدیت برای مخزن دارای تغییرات محلی tracked عمداً متوقف می‌شود،
  تا اصلاحات دستی از دست نروند.

پس از اتمام موفق، پیام `MASIHA_UPDATE_OK=<commit>` چاپ خواهد شد.

## ۳. بکاپ و بازیابی یک عملیات جداگانه است

ابتدا نسخه نرم‌افزار مقصد را نصب یا آپدیت کنید. سپس به‌صورت مستقل فایل
بکاپ رمزگذاری‌شده و کلید آن را از پنل مبدا دانلود و در پنل مقصد بارگذاری
کنید. در بازیابی قابل انتقال، آدرس، SSL و تنظیمات پنل مقصد حفظ می‌شود.
برای انتقال نهایی ربات، پردازشگر مبدا باید قبل از فعال کردن مقصد متوقف
و Snapshot نهایی گرفته شود. **آپدیت برنامه هرگز نشانه انتقال اطلاعات نیست.**

## بررسی ایمن بدون آپدیت

در مخزن نصب‌شده:

```bash
sudo bash /root/Masih-panel/deploy/update-existing.sh --check
```

این بررسی به دیتابیس‌ها دست نمی‌زند و فقط صحت پیش‌نیازهای برنامه را می‌سنجد.


## سرور مقصد هنوز صفحه وب مسیحا را ندارد

اگر مسیر /var/www/masiha-ui/ روی سرور مقصد وجود نداشته باشد،
دستور آپدیت آن را به‌طور خودکار از خروجی Build در مسیر موقت می‌سازد.
فقدان این پوشه دیگر خطا محسوب نمی‌شود. اگر پوشه از قبل وجود داشته باشد،
قبل از جایگزینی نسخه بازگشت تهیه می‌شود. آدرس صفحه /masiha-ui/
بعد از آپدیت نیز با درخواست محلی HTTPS بررسی خواهد شد. دیتابیس‌ها و
بکاپ‌های سرور قبلی در این مرحله منتقل یا بازیابی نمی‌شوند.


## بهینه‌سازی دائمی دانلود و کامپایل Go

در نسخه جدید، فرمان آپدیت ابتدا بررسی می‌کند که آیا GitHub Actions برای
هش دقیق Patch فعلی یک باینری از قبل ساخته است. در صورت موجود بودن:

1. فایل فشرده باینری 3x-ui از GitHub Releases دریافت می‌شود.
2. فایل SHA-256، شناسه Commit پایه پین‌شده و شناسه کامل Patch تطبیق داده می‌شوند.
3. باینریِ معتبر به کش اختصاصی همان Patch منتقل می‌شود.
4. فقط سورس و وابستگی‌های رابط وب با Node/Vite آماده می‌شوند؛ هیچ دانلود
   ماژول Go و هیچ کامپایل Go روی VPS انجام نمی‌شود.
5. راه‌اندازی نسخه جدید همچنان با نسخه بازگشت و بررسی سلامت سرویس‌ها انجام می‌شود.

ساخت باینری در GitHub Actions به‌صورت خودکار و تنها با تغییر فایل‌های
مرتبط انجام می‌شود. اگر خروجی موردنظر هنوز منتشر نشده یا دانلود آن
ناموفق باشد، آپدیتر به‌صورت ایمن به برای جلوگیری از معطلی کاربر **بدون کامپایل Go متوقف می‌شود** و به‌صراحت
می‌گوید انتشار باینری هنوز تکمیل نشده است. اگر مدیر بخواهد در شرایط اضطراری
ساخت محلی را فعال کند، می‌تواند `MASIHA_ALLOW_LOCAL_BUILD=1` را به
اسکریپت اصلی منتقل کند؛ در این حالت نیز کش مشترک Go حفظ می‌شود.

دو فرمان نصب و آپدیت **هیچ تغییری نکرده‌اند**؛ فقط مسیر داخلی آپدیت
سریع‌تر و قابل ازسرگیری شده است.

برای مشاهده وضعیت انتشار کامپایل‌شده:
https://github.com/masiweb/Masih-panel/actions/workflows/masiha-prebuilt-xui.yml

نشانگر `GO_COMPILATION=SKIPPED` در خروجی آپدیت به معنی استفاده واقعی
از نسخه آماده GitHub است. در صورت `No trusted precompiled release available`
انتشار هنوز کامل نشده یا GitHub Release در دسترس نیست و ساخت محلی
آغاز می‌شود.
