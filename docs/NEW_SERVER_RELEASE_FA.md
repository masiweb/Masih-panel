# بسته آزمایشی نصب سرور جدید — Masiha VPN Manager

**وضعیت:** کد نصب و آزمون‌های توسعه روی Ubuntu 24.04 سرور SentinelX `exon` با دامنه `exon.chanelchat.ir` بررسی شده است. نصب صفر تا صد دقیقاً با جدیدترین تغییرات هنوز باید روی یک ماشین تازه تکرار شود؛ نصب اولیه exon در نسخه قبلی موفق بود. نصب روی سرور تازه، اطلاعات کاربران/پرداخت/SSL/کلیدهای سرور توسعه را منتقل نمی‌کند.

## امکانات بسته

- پنل اختصاصی SANAei 3x-ui با رابط RTL ربات فروش، نمایش سفارش‌ها، پیام‌ها، پلن‌ها و پیام‌های ارسال‌نشده
- شش اینباند پایه Xray به‌علاوه سه اینباند افزایشی شامل Shadowsocks 2022 TCP/UDP و دو VLESS XHTTP TLS/H2؛ پورت‌های 8443 تا 8451، کلید Reality و TLS هر سرور مستقل
- یک حساب Xray با لینک اشتراک و پروفایل‌های OpenVPN/OpenConnect، سهمیه و تاریخ انقضای مشترک
- پلن‌های عادی یا رایگان تست، کیف پول، کارت‌به‌کارت با بررسی رسید مدیر، کد تخفیف، تمدید و سفارش‌های در انتظار
- **نام‌گذاری اشتراک توسط مشتری پیش از پرداخت:** پس از انتخاب پلن، نام ۲ تا ۵۵ کاراکتری با حروف فارسی/لاتین، عدد، فاصله، زیرخط یا خط تیره گرفته می‌شود. نام تکراری در میان سرویس‌های فعال، سفارش‌های ثبت‌شده و پیش‌فاکتورهای معتبر به‌صورت خودکار به `نام-abc12` تبدیل می‌شود؛ پسوند پنج حرف/عدد تصادفی است. نام در پیش‌فاکتور، رسید، سرویس و فهرست «سرویس‌های من» حفظ می‌شود. شناسه فنی `ms-...` برای ایمنی لینک‌ها تغییر نمی‌کند.
- کد تخفیف از مرحله نام‌گذاری عبور می‌کند؛ خرید کارت‌به‌کارت نام انتخابی را بعد از تأیید مدیر هم حفظ می‌کند؛ در خرید انبوه، از نام پایه و پسوندهای مستقل استفاده می‌شود. تمدید، نام فعلی را نگه می‌دارد.
- ربات تلگرام هنگام ساخت پلن تست رایگان از کاربر وجهی دریافت نمی‌کند؛ استفاده از تست برای هر شناسه تلگرام یک بار است.

## پیش‌نیازهای سرور تازه

- Ubuntu 24.04 **amd64** تازه و دسترسی root، بدون نصب قبلی x-ui یا Masiha
- دامنه با DNS A درست به IP همان سرور، پورت‌های ورودی 80/tcp و 443/tcp برای صدور TLS و پنل
- برای VPN: 1194/udp (OpenVPN)، 4443/tcp و 4443/udp (OpenConnect)، 8443 تا 8451/tcp برای ۹ Xray inbound و 8449/udp برای Shadowsocks
- در فایروال ارائه‌دهنده نیز این پورت‌ها باز باشند. `62053/tcp` و `2096/tcp` مدیریتی/داخلی هستند و نباید عمومی شوند.
- شبکه بتواند HTTPS به مخازن Go، Node، npm و GitHub برقرار کند؛ اسکریپت برای Go/Node آینه‌های جایگزین و IPv4→IPv6 دارد و برای بسته‌های Go محدودیت زمانی و fallback قرار می‌دهد.

## نصب روی سرور تازه (تنها روی سرور خالی)

```bash
sudo apt-get update
sudo apt-get install -y git python3
git clone https://github.com/masiweb/Masih-panel.git
cd Masih-panel
bash deploy/release-preflight.sh
sudo bash deploy/install-ubuntu-24.04.sh
```

اگر مخزن خصوصی است، از روش احراز هویت GitHub خودتان استفاده کنید؛ توکن را در خروجی گفتگو، دستور ذخیره‌شده یا تاریخچه shell قرار ندهید. در نصب تعاملی، دامنه و ایمیل Let's Encrypt پرسیده می‌شوند. در پایان **فقط پس از تأیید سرویس‌ها** نام کاربری و رمز تصادفی پنل نمایش داده می‌شود و نسخه حفاظت‌شده در `/root/masiha-vpn-initial-login.env` است.

پس از نصب:

```bash
cd ~/Masih-panel
sudo env MASIHA_EXPECT_DEFAULT_INBOUNDS=1 MASIHA_EXPECT_EXTRA_INBOUNDS=1 bash deploy/verify-install.sh
sudo certbot certificates
sudo systemctl status x-ui openvpn-server@masiha ocserv masiha-vpn-extension nginx --no-pager
```

اگر Git را در مسیر دیگری دریافت کرده‌اید، به همان مسیر وارد شوید. **روی سرورهایی که قبلاً x-ui نصب شده، اسکریپت نصب تازه را اجرا نکنید.**

### فقط در صورت توقف نصب پس از ایجاد پنل و SSL

اگر خطایی در مرحله ایجاد PKI/OpenVPN رخ داد و هنوز سرویس `masiha-vpn-extension.service` ساخته نشده است، پس از دریافت آخرین تغییرات و با حفظ CA و دیتابیس:

```bash
git pull --ff-only origin main
sudo bash deploy/finalize-ubuntu-24.04.sh --resume
```

این فرمان بازیابی عمومی همه خطاهای نصب نیست؛ اگر پیش‌شرط‌ها تطبیق نداشته باشند، متوقف می‌شود. خروجی خطا را بدون توکن و رمز گزارش کنید. فایل‌های `/etc/x-ui`، `/etc/openvpn/masiha/pki`، `/etc/letsencrypt` را برای حل خطا حذف نکنید.

## چک‌لیست تست بعد از نصب

1. HTTPS دامنه پنل را در مرورگر باز کنید؛ پنل روی `127.0.0.1:62053` در پشت Nginx باشد و گواهی صحیح LetsEncrypt نمایش داده شود.
2. شش اینباند پیش‌فرض را باز کنید؛ Reality کلید اختصاصی سرور دارد و بقیه با گواهی همان دامنه تنظیم شده‌اند.
3. بخش Subscription باید در مسیر `https://DOMAIN/sub/` و سرویس داخلی `127.0.0.1:2096` فعال باشد. یک کلاینت آزمایشی بسازید و URL واقعی اشتراک را از اینترنت دیگر بخوانید.
4. ربات: BotFather token و مدیر را وارد کنید، «بررسی اتصال» را بزنید، پلن عادی چنداینباندی بسازید؛ در تلگرام نام اشتراک انتخاب کنید و پرداخت آزمایشی کیف‌پول/رسید مدیر را بررسی کنید. یک نام تکراری باید پسوند **پنج‌کاراکتری** بگیرد.
5. پلن تست رایگان را بسازید و قابلیت تست را در تنظیمات فعال کنید. کاربر بدون پرداخت باید سرویس بگیرد و درخواست دوم رد شود.
6. در حساب ساخته‌شده، فایل‌های OpenVPN/OpenConnect و لینک‌های Xray را بررسی کنید؛ سپس اتصال واقعی از اینترنت بیرون، مصرف/انقضا و قطع دسترسی در اتمام حجم را تست کنید.
7. برای پرداخت آنلاین درگاه، محیط آزمایشی و فرآیند تأیید و تطبیق مبلغ واقعی را جداگانه تست کنید؛ موفق‌بودن تست‌های واحد به معنی تأیید درگاه زنده نیست.
8. اطلاعات ورود پنل، توکن ربات، رسیدها، رمزهای کاربران، کلید Reality و دیتابیس فروش **نباید وارد GitHub شوند**. قبل از ترافیک واقعی بکاپ خارج از سرور و بازیابی آن را آزمایش کنید.

## نتیجه آزمون واقعی ساخت روی سرور exon (Ubuntu 24.04.4)

این گزارش مربوط به **خود سرور تازه exon** است، نه صرفاً سرور توسعه قدیمی:

- اجرای GitHub از commit پین‌شده 3x-ui و اعمال کامل patch اختصاصی موفق بود.
- نصب ۵۹۳ وابستگی npm و ساخت frontend TypeScript + Vite با موفقیت تمام شد.
- در prefetch، مخزن Aliyun برای ماژول `github.com/sagernet/sing-shadowsocks@v0.2.9` پاسخ `404` داد؛ انتقال خودکار به `goproxy.cn` موفق شد. به همین دلیل fallback واقعی شبکه در این محیط آزموده شده است.
- پس از تکمیل کش Go، کامپایل backend با `GOPROXY=off` و `GOMAXPROCS=2` به **BUILD PASS** رسید؛ باینری ۱۰۱٬۰۸۴٬۹۲۸ بایتی تولید و فایل `x-ui.sha256` تأیید شد.
- اجرای دوباره `deploy/build-3x-ui.sh` همان patch و باینری سالم را تشخیص داد و بدون دانلود یا کامپایل مجدد به **BUILD PASS** رسید.
- preflight نسخه نهایی شامل ۴ تست ایزوله ساخت پیش‌فرض Xray و ۴۴ تست ربات/فروش/سهمیه با موفقیت عبور کرد. این تست‌ها به سرویس‌ها و دیتابیس‌های واقعی دست نمی‌زنند.
- **نصب کامل روی exon انجام شد:** دامنه `exon.chanelchat.ir` به IP `82.47.63.15` متصل است؛ Certbot گواهی معتبر Let's Encrypt با انقضای ۹ ژانویه ۲۰۲۷ صادر کرد. پنل از مسیر `https://exon.chanelchat.ir/xui/` با HTTP 200 و بررسی معتبر TLS پاسخ داد. Nginx، x-ui، OpenVPN، ocserv و سرویس Masiha Extension فعال شدند.
- **شش اینباند پیش‌فرض Xray ساخته شدند و در حال شنود هستند:** پورت‌های 8443 تا 8448/tcp؛ subscription `https://exon.chanelchat.ir/sub/` از سرویس داخلی 127.0.0.1:2096 عبور می‌کند. پورت پنل 62053 فقط به loopback متصل است.
- **آزمون واقعی تونل‌ها روی exon موفق بود:** با حساب و network namespace موقت، OpenVPN و OpenConnect هر دو TLS/auth/handshake و دسترسی اینترنت از مسیر VPN را گذراندند. پس از غیرفعال‌سازی حساب موقت، online count برای هر دو صفر شد؛ اسکریپت تست به دامنه و IPv4 فعلی سرور وابسته شده و دیگر از IP ثابت سرور توسعه قدیمی استفاده نمی‌کند.
- **آزمون امن API پنل موفق بود:** لاگین مدیریتی، نیاز به احراز هویت، الزام CSRF و مخفی ماندن توکن ربات در پاسخ API با دیتابیس ایزوله تأیید شد. این smoke test اکنون در `deploy/verify-install.sh` اجرا می‌شود.
- روی exon تنظیمات ربات تلگرام هنوز توکن/ادمین ندارد؛ ارسال به کاربر تلگرام و پرداخت آنلاین واقعی تا زمان ثبت تنظیمات قابل آزمون نیست. اتصال واقعی همه شش پروتکل Xray، پایان سهمیه مشترک و تمدید SSL نیز هنوز نیاز به تست جداگانه دارند.
- در این محیط SentinelX، عامل ابتدا `NoNewPrivileges=yes` داشت و نمی‌توانست `sudo` اجرا کند؛ پس از اصلاح با دسترسی مستقیم مدیر سرور، اجرای root از agent موفق شد. این مسئله مربوط به سطح دسترسی SentinelX است، نه به Python پروژه. برای محیط‌های عملیاتی، بعد از اتمام توسعه سطح دسترسی عامل را محدود کنید.

## بازیابی تست‌شده ورود اولیه مدیر (exon)

پس از نصب موفق `exon` مشاهده شد که فایل `/root/masiha-vpn-initial-login.env` کاربر `admin` را گزارش می‌کند ولی کاربر ذخیره‌شده در دیتابیس فعال x-ui هنوز نام تصادفی upstream است. به همین دلیل لاگین و اتصال داخلی ماژول فروش شکست می‌خوردند. رمز اولیه‌ای که در گفتگو نمایش داده شد فوراً منقضی و یک رمز جدید تصادفی صادر شد. ابزار `deploy/repair-panel-login.sh` به‌صورت محدود و تنها برای نصب اولیه بدون مشتری اجرا شد؛ بکاپ پیش از تغییر گرفت، اعتبارنامه واقعی SQLite را ثبت و با دو فایل دارای سطح دسترسی `0600` همگام کرد. **درخواست ورود واقعی از HTTP محلی و دسترسی احراز هویت‌شده به API فروش با رمز جدید موفق بود**. هر پنج سرویس مجدداً فعال شدند و `https://exon.chanelchat.ir/xui/` با HTTPS معتبر پاسخ `200` داد. رمز جدید در گزارش یا Git منتشر نشده است.

نصب‌کننده برای سرورهای تازه اصلاح شد تا پس از خاموش‌کردن x-ui، اعتبارنامه تصادفی اولیه را با اعتبارنامه مدیر انتخاب‌شده جایگزین و **مجدداً در SQLite تأیید کند**؛ سپس ورود واقعی را با `deploy/check-panel-login.py` پیش از فعال‌سازی سرویس فروش کنترل کند. `deploy/verify-install.sh` نیز این کنترل را به‌صورت الزامی تکرار می‌کند. **اطلاعات ورود فقط بعد از قبولی آزمون‌های حقیقی و سلامت سرویس‌ها در انتهای نصب روی ترمینال نشان داده می‌شوند**. ابزار بازیابی برای نصب‌های قدیمی بدون مشتری باقی می‌ماند و از تغییر حساب‌های موجود جلوگیری می‌کند.

## بازیابی مرحله نهایی و تکمیل نصب exon — ۱۲ اکتبر ۲۰۲۶

یک نصب تازه پس از ساخت موفق شش inbound و آماده‌سازی PKI هنگام `Verify real administrator login` متوقف شده بود. نشانگر امن `/etc/masiha-vpn-extension/.finalize-in-progress`، فایل‌های گواهی و دیتابیس x-ui در سرور حفظ شده بودند. پس از دریافت patch جدید، **همان نصب با `sudo bash deploy/finalize-ubuntu-24.04.sh --resume`** بدون نصب مجدد یا حذف PKI تکمیل شد.

- پیش از ادامه، `deploy/check-panel-login.py` با اطلاعات root-only یک درخواست واقعی ورود را با موفقیت آزمود؛ سه تست شبیه‌سازی‌شده تأخیر راه‌اندازی، رد اعتبارنامه و ناهماهنگی SQLite هم موفق بودند.
- بازیابی واقعی `--resume` در حدود ۱۳ ثانیه به موفقیت رسید؛ **هر پنج سرویس** x-ui، Nginx، OpenVPN، ocserv و افزونه Masiha فعال شدند.
- آزمون `MASIHA_EXPECT_DEFAULT_INBOUNDS=1 bash deploy/verify-install.sh` با موفقیت تمام شد: شش inbound فعال، پورت‌های ۸۴۴۳–۸۴۴۸، HTTPS subscription روی `/sub/`، ورود واقعی مدیر، APIهای احراز هویت‌شده OpenVPN/OpenConnect/فروش و محافظت CSRF تأیید شد.
- HTTP عمومی `https://exon.chanelchat.ir/xui/` پاسخ `200` و اعتبار SSL برابر `0` (بدون خطای TLS) بود. دو فایل اعتبارنامه root-owned با دسترسی `0600` کاملاً یکسان‌اند، دیتابیس بدون مشتری است و marker نصب نیمه‌تمام پاک شده است.
- روی نسخه نصب‌شده **۵۱ تست ایزوله** (۴۴ فروش/سهمیه، ۴ ساخت پیش‌فرض، ۳ کنترل ورود) موفق شدند.
- هنوز توکن، مدیران و پلن‌های فروش ربات در exon تنظیم نشده‌اند؛ تست ارسال پیام واقعی و تراکنش پرداخت در این سرور انجام نشده است.
- **آزمون ترافیک واقعی OpenConnect در اولین تلاش ناموفق بود:** اسکریپت آزمایشی `test-oc-route.sh` توسط نصب‌کننده با مجوز `0644` کپی شده و اجرای آن با پیام `Permission denied` شکست خورد؛ در نتیجه مسیر پیش‌فرض تونل فعال نشد و curl timeout داد. نصب‌کننده اکنون آن را با مجوز `0755` نصب می‌کند و `verify-install.sh` اجرایی‌بودن هر دو helper مربوط به VPN را کنترل می‌کند. مجوز روی exon اصلاح و تست تکرار شد: OpenVPN و OpenConnect هر دو اتصال TLS/Auth، عبور واقعی اینترنت با IP سرور و قطع دسترسی پس از غیرفعال‌سازی را با موفقیت گذراندند. کاربران آزمایشی به‌صورت خودکار حذف شدند.

## توسعه پنل فروش و اینباندهای جدید روی exon

در اکتبر ۲۰۲۶ مشکل پنهان‌ماندن پلن تست رایگان رفع شد: هنگام ساخت/فعال‌سازی پلن تست، سوئیچ سراسری ارائه تست خودکار روشن می‌شود و کاربر فاقد سفارش تست قبلی با ارسال `/start` منوی دریافت تست را می‌بیند. منوی مدیریت داخل تلگرام برای مدیران مجاز اضافه شد؛ رمزها/توکن‌های اصلی و متن‌های پیش‌فرض تنها در پنل وب تغییر می‌کنند. صفحه وب اکنون تب «متن‌های پیش‌فرض» با ۱۸ پاسخ قابل‌ویرایش دارد. گزینه `require_contact` اعتبارسنجی شماره متعلق به کاربر تلگرام را فعال/غیرفعال می‌کند.

روی exon سه اینباند `8449` Shadowsocks 2022 TCP/UDP و `8450,8451` XHTTP/TLS/H2 با قابلیت افزودن و حذف کلاینت، از API واقعی 3x-ui آزمایش شدند و لینک‌های استاندارد `ss://` و `vless://` تولید کردند. افزودن اینباندها و راه‌اندازی مجدد x-ui بدون حذف شش اینباند قبلی یا مشتریان انجام شد. **Shadowsocks 2022 در Xray جدید deprecation warning دارد؛ اولویت توصیه‌شده XHTTP است.** آزمون اتصال واقعی این سه پروتکل از ISPهای ایران هنوز باقی است و موفقیت در دورزدن فیلترینگ تضمین نمی‌شود.

```bash
# مخصوص سروری که از قبل Masiha نصب شده و نیاز به سه اینباند افزایشی دارد:
# قبل از اجرای ابزار، از دیتابیس /etc/x-ui/x-ui.db بکاپ معتبر تهیه کنید،
# سپس x-ui را موقتاً متوقف کنید.
sudo systemctl stop x-ui
sudo python3 deploy/extend-inbounds.py --domain YOUR.DOMAIN
sudo systemctl start x-ui
sudo env MASIHA_EXPECT_EXTRA_INBOUNDS=1 bash deploy/verify-install.sh
```

این ابزار برای افزودن ایمن، فقط پورت‌ها و تگ‌های خود را ایجاد می‌کند و اینباندهای موجود را بازنویسی نمی‌کند؛ اجرای مجدد آن idempotent است. نصب و استقرار فایل‌های جدید رابط وب روی سرور موجود نیاز به فرایند build و جایگزینی باینری دارد؛ ابزار بالا فقط افزودن inbound است.

## اعتبارسنجی توسعه تکمیلی ربات و Shadowsocks — exon

روی exon سازگاری patch رابط وب با upstream پین‌شده بررسی شد، TypeScript و Vite ساخته شدند و باینری Go جدید با موفقیت اجرا شد. API وب ۱۸ متن پیش‌فرض قابل‌ویرایش و تنظیم فعال تست را نمایش می‌دهد؛ یک دکمه تست رایگان با دیتابیس واقعی اما بدون ارسال پیام به کاربر بررسی شد. مدیریت تلگرامی در یک کپی ایزوله از دیتابیس واقعی تست شد و کاربر غیرمدیر رد شد.

Xray سه اینباند افزودنی را ساخت و هر سه در native 3x-ui فعال هستند. با کلاینت موقت امکان الصاق به هر سه و دریافت لینک‌های `ss://` و `vless://` تأیید و سپس کلاینت حذف شد. **این تست کارکرد کلاینت روی شبکه‌های ایران را تضمین نمی‌کند.** در آزمون ایزوله جدید، کدهای مدیریت تلگرام از ارسال همگانی بدون تأیید دوم و ثبت اعتبار پس از ترک فرم جلوگیری می‌کنند.

## توسعه باشگاه امتیاز و سرگرمی روی exon — ۱۲ اکتبر ۲۰۲۶

نسخه جدید شامل **کارت مدیریتی کاربر** (تصویر پروفایل در صورت ارائه از سوی Telegram API، مشخصات، شماره، کیف پول، امتیاز و دعوت‌ها)، دکمه «لیست اشتراک‌های خریداری‌شده» با نمایش جزئیات سرویس، و ناوبری همیشه‌در‌دسترس خانه/سرگرمی/امتیازها است. در مراحل ورود متن، دکمه انصراف/بازگشت باقی می‌ماند.

به ربات چهار زیرمنوی **هوش مصنوعی، موزیک، فیلم و بازی** اضافه شد. در وضعیت فعلی، موزیک/فیلم/بازی صفحه آغازین دارند و هنوز به سرویس محتوا یا بازی اجرایی متصل نیستند. هوش مصنوعی از طریق یک API سازگار با Chat Completions و HTTPS عمومی پشتیبانی می‌شود، ولی **تا ثبت URL، مدل و کلید محرمانه در وب غیرفعال می‌ماند**. تعداد درخواست‌های موفق با امتیاز کاربران محدود می‌شود و در صورت خطای API امتیاز کم نمی‌شود. کلید API در خروجی پنل یا پیام تلگرام منتشر نمی‌شود.

قوانین امتیاز قابل تنظیم‌اند: امتیاز به‌ازای واحدهای کامل مبلغ **واقعی سفارش تحویل‌شده** و امتیاز **یک‌باره** برای دعوت‌شده‌ای که الزامات عضویت و شماره تماس را طی کرده است. جدول `loyalty_points` و `ai_usage` به صورت افزایشی ساخته می‌شوند؛ هیچ کاربر یا سفارش قدیمی حذف نمی‌شود. پیش‌فرض: هر ۱۰۰٬۰۰۰ تومان خرید = ۱۰ امتیاز، هر دعوت موفق = ۲۰ امتیاز، هزینه پاسخ AI = ۵ امتیاز. برای سوابق قبل از فعال‌سازی، امتیاز خودکار و بدون تأیید مدیر ایجاد نشده است.

روی `exon` بکاپ SQLiteهای فروش، پنل و VPN و باینری/رابط وب پیش از تغییرات تهیه شد. رابط React با TypeScript و Vite و باینری Go جدید با موفقیت ساخته و نصب شدند. **۶۴ تست فروش/ربات/وفاداری + ۱۱ تست نصب و پیکربندی** موفق شدند. API وب بخش امتیازات را بازمی‌گرداند، کلید API را مخفی می‌کند، پنل HTTPS پاسخ معتبر دارد و پنج سرویس اصلی فعال‌اند. کارت مدیر و منوهای سرگرمی در کپی ایزوله از دیتابیس واقعی آزموده شدند، بدون ارسال پیام به مشترکان.

## کتابخانه موزیک، فیلم، سریال و رقابت کاربران (exon، اکتبر ۲۰۲۶)

فاز جدید در `exon` مستقر شد: تشخیص خودکار فایل صوتی/تصویری و فیلم یا موزیک فورواردشده از تلگرام، شناسایی مستقیم لینک‌های HTTPS با پسوند رسانه، تکمیل اختیاری اطلاعات موزیک و مشخصات کامل فیلم/سریال و کاور، ۲۰ رسانه آخر، رسانه‌های شخصی، جست‌وجو، پلی‌لیست‌های عمومی/خصوصی با دعوت اختصاصی، محبوب‌ترین‌ها، لایک و نظر و جدول برترین سازندگان بر اساس پلی‌لیست و لایک.

- برای فایل‌های تلگرام فقط `file_id` و `file_unique_id` ذخیره می‌شود؛ در زمان پخش ربات همان فایل را از Telegram Bot API دوباره ارسال می‌کند. **هیچ دانلود، تبدیل یا آرشیو بایت رسانه‌ای در VPS انجام نمی‌شود**. لینک HTTPS خارجی بدون انتقال فایل ذخیره می‌شود و همچنان به میزبان لینک وابسته است.
- امتیاز هر فیلد اختیاری پیش‌فرض ۲، امتیاز لایک به سازنده ۱؛ سقف روزانه به‌ترتیب ۳۰ و ۲۰ امتیاز. پاداش فراداده **تنها پس از انتشار** اعمال می‌شود و مرحله جداگانه تأیید مجوز از گردش کار حذف شده است. فایل تکراری، لایک صاحب محتوا یا حذف/لایک مجدد پاداش جدید ایجاد نمی‌کند.
- مدیران در وب تب «کتابخانه موزیک و فیلم» را با تنظیمات امتیاز و گزارش‌های حقوق نشر دارند؛ از ربات نیز گزارش‌ها را بررسی، رسانه را پخش و در صورت تأیید تخلف از دسترس خارج می‌کنند. حذف شخصی به تأیید دوم نیاز دارد.
- در استقرار زنده، بکاپ کامل SQLite دیتابیس فروش، x-ui و کاربران VPN و باینری/UI گرفته شد: `/opt/masiha-vpn-extension/backups/media-platform-20261012-091820/`. سرویس افزونه و x-ui بعد از راه‌اندازی فعال هستند. نسخه React/TypeScript، Vite و Go با موفقیت ساخته و مستقر شد.
- آزمون انتهابه‌انتها با **دو حساب ساختگی در کپی جداگانه دیتابیس واقعی** موفق بود: دریافت فایل صوتی، تکمیل اطلاعات، ثبت امتیاز بعد از انتشار، پخش از `file_id`، لایک، ساخت پلی‌لیست خصوصی، جلوگیری از مشاهده پیش از دعوت، پذیرش دعوت، ارسال نظر و جست‌وجو. هیچ پیام یا فایل مصنوعی برای کاربران واقعی ارسال نشده است.
- **آخرین سنجش: ۹۴ تست ایزوله** (۸۳ فروش/رسانه/ربات + ۱۱ نصب)؛ علاوه بر بررسی عملی مجدد API زنده و سرویس‌ها. **تست ارسال/پخش یک موزیک یا فیلم واقعی در کلاینت تلگرام کاربر هنوز جداگانه لازم است**. نصب صفر تا صد همین commit روی VM کاملاً جدید هنوز تکرار نشده است.

راهنما و محدودیت‌ها: [کتابخانه موزیک و فیلم](MEDIA_LIBRARY_FA.md).

## شناسایی فرمت‌های بیشتر و ثبت ساده رسانه — توسعه exon

فایل‌های صوتی MP3، M4A، AAC، FLAC، WAV، OGG، OPUS و سایر پسوندهای رایج صدا، همچنین MP4، MKV، AVI، MOV، WEBM، MPEG، WMV، 3GP و دیگر پسوندهای رایج ویدئو از روی نوع تلگرام، MIME معتبر یا پسوند شناسایی می‌شوند. برای مدارک ناشناس، فایل‌های اجرایی یا MIME متناقض ثبت خودکار انجام نمی‌شود.

**مرحله جداگانه تأیید حق نشر حذف شده است.** پس از مراحل اختیاری اطلاعات و کاور، ثبت مستقیم انجام می‌شود و پاداش فراداده فقط پس از انتشار ثبت می‌گردد. دکمه تأیید قدیمی برای پیش‌نویس‌های بازمانده از نسخه‌های قبلی به‌صورت سازگار پشتیبانی می‌شود؛ هیچ دکمه مجوز جدیدی نمایش داده نمی‌شود. امکان گزارش و حذف محتوای نامناسب یا بدون مجوز توسط مدیر حفظ شده است. پیام‌های اصلی راهنما و توضیح رسانه کوتاه‌تر شده‌اند.

این تغییر روی exon با بکاپ دیتابیس فروش و فایل‌های فعلی Python، اجرای **۹۳ تست** روی نسخه نصب‌شده و راه‌اندازی مجدد سالم ربات تأیید شد.

## وضعیت کیفیت نسخه

- آزمایش **۶۲ تست ایزوله** در نسخه جدید: ۵۱ آزمون فروش/ربات و سهمیه و ۱۱ آزمون نصب/احراز هویت و اینباندهای پایه و افزایشی روی Ubuntu 24.04.4 با موفقیت انجام شد (عدد نهایی را با `bash deploy/release-preflight.sh` روی commit خودتان مجدداً بررسی کنید).

- **نصب صفر تا صد Ubuntu 24.04 با این نسخه در exon موفق بود.** تونل‌های واقعی OpenVPN/OpenConnect و API پنل تأیید شدند؛ اتصال واقعی کلاینت به شش نوع Xray، سقف مصرف/انقضای بین‌پروتکلی، ارسال Telegram و پرداخت درگاه زنده هنوز جداگانه نیازمند تأیید هستند.
