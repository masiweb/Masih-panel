# پشتیبان‌گیری کامل و انتقال بین سرورها — VPN Manager

این قابلیت روی سرور توسعه `exon.chanelchat.ir` طراحی شده و **بکاپ واقعی و بازیابی ایزوله** آن آزمایش شده است. دستورات را با کاربر `root` و در یک ماشین نصب‌شده Ubuntu 24.04 اجرا کنید. خود بکاپ *پروفایل‌های کنونی Xray*، کلاینت‌ها، نودها، مصرف/سهمیه، دسترسی و تراکنش‌های ربات را به همان وضعیت زمان بکاپ منتقل می‌کند.

## چه چیزهایی در بسته است؟

- **SQLite پنل `/etc/x-ui/x-ui.db`:** تمام جدول‌ها، کاربران پنل، تنظیمات، اکانت‌ها، نودها و ارتباط نود/کلاینت، اینباندها و تنظیماتشان، کلاینت‌ها و اتصال آن‌ها به اینباندها، IPها، تاریخچه و گزارش‌های مصرف، شمارنده‌های ترافیک، اشتراک‌ها، توکن‌ها و وضعیت‌های لازم. تمام جداول موجود، نه فقط جداول ازپیش‌تعریف‌شده، حفظ می‌شوند.
- **SQLite کاربران VPN `/etc/masiha-vpn-extension/users.db`:** شناسه‌های مشترک OpenVPN و OpenConnect، اطلاعات کاربر و تاریخچه.
- **SQLite ربات `/etc/masiha-vpn-extension/sales/sales.db`:** پلن‌ها، سفارش‌ها، رسیدها، شارژها، کیف پول و دفتر مالی، کد تخفیف، امتیاز، کاربران تلگرام، تنظیمات بات، قالب‌های پاسخ، ثبت استفاده AI، رسانه‌های ثبت‌شده و پلی‌لیست‌ها، پیام‌های صف، تیکت‌ها و سایر جدول‌های موجود.
- **پیکربندی و کلیدها:** پوشه OpenVPN شامل CA/PKI، گواهی‌ها، کلید `tls-crypt` و فایل‌های پروفایل؛ تنظیمات سرور OpenVPN؛ حساب‌های ocserv و تنظیمات OpenConnect؛ گواهی‌ها و کلیدهای Let's Encrypt، Nginx، تنظیمات systemd، تنظیمات پنل و افزونه.
- **نسخه اجرایی دقیق پنل و Xray، GeoData و کد اجرایی افزونه.** پوشه‌های build، toolchain، کش، فایل‌های قفل، WALهای موقت و بکاپ‌های قدیمی عمداً مستثنا هستند تا آرشیو رشد بی‌پایان نداشته باشد.
- **تنظیمات شبکه:** فایل‌های مرتبط Nginx/UFW/iptables و `sysctl`، به‌علاوه گزارش رمزگذاری‌شده وضعیت فعلی route/NAT/firewall برای بازبینی. قوانین فعال runtime را کورکورانه روی سرور جدید اعمال نمی‌کنیم، زیرا ممکن است SSH قطع شود.

فایل‌های رسانه‌ای تلگرام روی سرور تلگرام هستند: دیتابیس فقط file_id، لینک، اطلاعات و پلی‌لیست را منتقل می‌کند. اگر فایل تلگرامی حذف شده باشد، هیچ بکاپ سروری نمی‌تواند آن فایل را بازگرداند. همچنین **مشخصات اتصال نودهای خارجی به‌معنای انتقال فیزیکی آن نودها نیست**؛ نود خارجی باید جداگانه آنلاین و با مقصد جدید هماهنگ شود.

## ویژگی‌های امنیتی و صحت

- خروجی پیش‌فرض با `GPG AES-256` و رمز مستقل ۲۵۶بیتی رمزگذاری می‌شود.
- کلید فقط یک بار در `/root/.masiha-backup.key` ایجاد می‌شود، با دسترسی `600`. در GitHub یا پیام‌رسان منتشر نمی‌شود.
- فایل `.sha256` و checksum تک‌تک فایل‌ها در manifest داخلی کنترل می‌شوند. بکاپ SQLite از API رسمی backup تهیه می‌شود، نه `cp` از دیتابیس فعال.
- هر سه دیتابیس پس از بازیابی با `PRAGMA integrity_check` بررسی می‌شوند.
- نام مسیرهای مقصد فقط در فهرست مجاز بررسی می‌شوند؛ symlinkهای TLS نیز محدود به ساختار معتبر Let's Encrypt هستند.
- بازیابی زنده بدون `--confirm-restore` انجام نمی‌شود؛ پیش از آن بکاپ **رمزگذاری‌شده** از وضعیت مقصد گرفته می‌شود. در خطای جایگزینی یا تست پیکربندی، ابزار تلاش به rollback می‌کند.
- چون دو سرور با یک توکن تلگرام نباید هم‌زمان به `getUpdates` متصل باشند، سرویس `masiha-vpn-extension` روی مقصد به‌صورت پیش‌فرض پس از بازیابی خاموش می‌ماند. بعد از توقف بات در سرور قدیمی، آن را دستی فعال کنید.

## ۱) بکاپ گرفتن روی exon

```bash
cd /root/Masih-panel
git pull --ff-only origin main
sudo python3 deploy/full-backup.py backup
```

در حالت پیش‌فرض سرویس‌ها قطع نمی‌شوند. هر دیتابیس جداگانه snapshot سازگار دارد ولی امکان اختلاف چندثانیه‌ای میان ثبت‌های هم‌زمان دیتابیس‌های مختلف هست. **برای انتقال نهایی و دقیق** پس از توقف پذیرش سفارش و در بازه انتقال، از گزینه زیر استفاده کنید:

```bash
sudo python3 deploy/full-backup.py backup --quiesce
```

این حالت در زمان گرفتن snapshot سرویس‌های مرتبط را **کوتاه‌مدت متوقف و سپس دوباره فعال** می‌کند؛ ممکن است کاربران VPN قطع موقت داشته باشند. هنگام انتقال نهایی، برای جلوگیری از دوگانگی پرداخت باید فعال‌شدن دوباره ربات روی سرور مبدأ نیز طبق زمان cutover کنترل شود.

خروجی در `/root/masiha-backups/masiha-full-<DOMAIN>-<UTC>.tar.gz.gpg` است. **فقط فایل `.gpg` + فایل `.sha256` + فایل کلید خصوصی** برای جابه‌جایی نیاز است.

## ۲) صحت‌سنجی روی سرور مبدأ

```bash
sudo python3 deploy/full-backup.py verify \
 /root/masiha-backups/masiha-full-<DOMAIN>-<UTC>.tar.gz.gpg
```

اگر رمز اشتباه باشد، checksum تغییر کرده یا یک دیتابیس ناقص باشد، کار متوقف می‌شود.

## ۳) انتقال امن به سرور جدید

از طریق SSH/SCP یا SFTP با کانال رمزگذاری‌شده، موارد زیر را به سرور مقصد منتقل کنید:

```text
/root/masiha-backups/masiha-full-....tar.gz.gpg
/root/masiha-backups/masiha-full-....tar.gz.gpg.sha256
/root/.masiha-import.key  ← کپیِ کلید مبدأ با نام متفاوت روی مقصد
```

فایل بکاپ و **کلید رمزگشایی را به هیچ عنوان** در مخزن GitHub، فضای عمومی، سرویس فایل اشتراکی باز یا پیام تلگرام ارسال نکنید. بهتر است کلید را از کانال مستقلی انتقال دهید. در مقصد کلید مبدأ را با **نام متفاوت** `/root/.masiha-import.key` نگه دارید و `chmod 600 /root/.masiha-import.key` کنید. کلید قدیمی خود مقصد (`/root/.masiha-backup.key`) را با کلید مبدأ جایگزین نکنید؛ کلید مقصد برای بکاپ پیش از restore استفاده می‌شود.

ابتدا Ubuntu 24.04 و نسخه پروژه VPN را از GitHub روی مقصد نصب کنید تا بسته‌های OpenVPN، ocserv، Nginx، Xray و سرویس‌ها وجود داشته باشند. **از اجرای هم‌زمان بات روی مبدأ و مقصد بپرهیزید.** قبل از restore فایل‌های مقصد را از تنظیمات دلخواه خودتان نیز بکاپ بگیرید.

## ۴) بازیابی آزمایشی، بدون دستکاری سرویس‌های واقعی

```bash
cd /root/Masih-panel
sudo mkdir -m 700 /tmp/masiha-restore-check
sudo python3 deploy/full-backup.py restore /root/masiha-full-....tar.gz.gpg \
  --key-file /root/.masiha-backup.key \
  --confirm-restore --staging-root /tmp/masiha-restore-check
```

خروجی را بررسی کنید. این مرحله اطلاعات زنده یا بات را عوض نمی‌کند؛ فقط زیر `/tmp/masiha-restore-check` فایل‌ها را بازسازی و دیتابیس‌ها را اعتبارسنجی می‌کند.

## ۵) بازیابی نهایی روی مقصد — فقط پس از تأیید

**حالت پیشنهادی:** مقصد همان `exon.chanelchat.ir` را پس از انتقال DNS یا تنظیم نام دامنه در نصب اولیه استفاده کند؛ دامنه پشتیبان و مقصد باید یکسان باشد.

```bash
sudo python3 /root/Masih-panel/deploy/full-backup.py restore \
  /root/masiha-full-....tar.gz.gpg \
  --key-file /root/.masiha-import.key --confirm-restore
```

فرآیند در حالت پیش‌فرض:
1. تمام checksumها و سلامت دیتابیس‌ها را بررسی می‌کند.
2. تطبیق دامنه را بررسی می‌کند.
3. بکاپ رمزگذاری‌شده مجزایی از مقصد می‌گیرد.
4. سرویس‌های مربوط را متوقف، فایل‌های فعلی را محفوظ و نسخه پشتیبان را بازیابی می‌کند.
5. پیکربندی Xray، Nginx و OpenConnect و سلامت سه دیتابیس را بررسی می‌کند.
6. سایر سرویس‌ها را برمی‌گرداند ولی **بات تلگرام و افزونه را خاموش** نگه می‌دارد.
7. پس از توقف سرویس بات روی مبدأ، مدیر در مقصد اجرا می‌کند:

```bash
sudo systemctl stop masiha-vpn-extension.service  # روی مبدأ
# پس از اطمینان از غیرفعال شدن مبدأ، روی مقصد:
sudo systemctl start masiha-vpn-extension.service
```

فقط اگر از قبل **مطمئنید بات مبدأ کاملاً متوقف است**، گزینه `--activate-telegram` را به فرمان restore اضافه کنید.

اگر دامنه مقصد متفاوت باشد، Restore **به‌صورت پیش‌فرض متوقف می‌شود**. پارامتر پیشرفته `--allow-domain-mismatch` تنها با علم به نیاز تغییر دستی تمام لینک‌ها، DNS، Nginx، گواهی TLS، تنظیمات subscription، مسیرهای ارتباطی نودها و بررسی Reality مجاز است. فعال‌سازی آن هیچ جایگزینی خودکار دامنه‌ای انجام نمی‌دهد؛ بدون انجام این تنظیمات، سرویس‌ها ممکن است کار نکنند.

## ۶) کنترل بعد از انتقال

```bash
cd /root/Masih-panel
sudo bash deploy/verify-install.sh
sudo systemctl status x-ui ocserv openvpn-server@masiha nginx --no-pager
```

سپس در مرورگر و تلگرام بررسی کنید: ورود مدیر، تعداد مشتری و اینباند، صفحات نودها، لینک subscription، حجم/انقضای یک اشتراک قدیمی، پروفایل OpenVPN و OpenConnect، موجودی کیف پول، سفارش‌های در انتظار، رسیدها و عملکرد بات. برای جلوگیری از مشکلات DNS و مسیر شبکه، **خود اتصال VPN را از اینترنت واقعی مشتری هم تست کنید**. پورت‌های موردنیاز باید در فایروال ارائه‌دهنده نیز باز باشند.

**مهم:** تست اجرای restore روی یک VPS تازه در این مرحله انجام نشده است. تا پیش از تست کامل روی مقصد، سرور قدیمی و بکاپ قبلی را حذف نکنید. در صورت خطا ابزار rollback محلی را امتحان می‌کند، اما در خطاهای شدید OS/شبکه ممکن است بازگردانی دستی لازم شود.
