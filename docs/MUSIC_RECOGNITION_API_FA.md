# اتصال شناسایی صوتی به سرویس AcoustID

بعد از دریافت Voice (۵ تا ۴۵ ثانیه) و دانلود موقت آن از تلگرام، موتور Chromaprint با ابزار fpcalc اثرانگشت استاندارد تولید می‌کند؛ سپس با درخواست POST روی HTTPS و بدون ارسال خود فایل صوتی، نتیجه شناسایی شامل نام اثر و خواننده را از API AcoustID می‌گیرد. با تطبیق نام آهنگ و خواننده روی رسانه‌های منتشرشده در دیتابیس، دکمه پخشِ موزیکِ موجود برمی‌گردد. اگر API شناسایی کند اما موزیک در آرشیو نباشد، نام و خواننده همراه پیغام نبودن در آرشیو نمایش داده می‌شود. اگر API قطع باشد، موتور audfprint محلی حفظ شده است.

شناسه audio_fp_index.fingerprint_id شناسه داخلی نمایه محلی است و با fingerprint استاندارد Chromaprint متفاوت است؛ برای درخواست API باید اثرانگشت استاندارد صوت محاسبه شود.

**مجوز:** AcoustID رایگان فقط برای کاربرد غیرتجاری است. ربات فروش تجاری باید با کلید/قرارداد مناسب و مجوز ارائه‌دهنده استفاده شود. کلید نمونه مستندات موقتی است و در تولید نباید استفاده شود.

تنظیم سرویس در /etc/masiha-vpn-extension/sales/audio_recognition.json با مجوز فایل 0600:

{
  "provider": "acoustid",
  "enabled": true,
  "client_key": "REPLACE_WITH_YOUR_LICENSED_APPLICATION_KEY"
}

فایل نمونه با enabled=false ساخته می‌شود تا بدون کلید مجاز، ارتباط خارجی انجام نشود. این مسیر در گیت قرار نمی‌گیرد. هنگام تغییر فایل تنظیمات، worker زمان‌بندی‌شده در نوبت بعدی تغییر را می‌خواند. نصب ابزار fpcalc با بسته libchromaprint-tools توسط اسکریپت نصب اثرانگشت انجام می‌شود.

امنیت: فایل صوتی صرفاً در پوشه موقت قرار می‌گیرد و پس از جستجو پاک می‌شود. تنها اثرانگشت استاندارد و مدت زمان به AcoustID فرستاده می‌شود. کلید API و اثرانگشت ارسالی در دیتابیس و لاگ‌ها ذخیره نمی‌شود. نتیجه‌ی ضعیف یا مشکوک باعث پیشنهاد موزیک اشتباه از آرشیو نمی‌شود. شناسایی برای آثار فارسی موجود در AcoustID تضمین‌شده نیست.
